# AGENTS.md — `LuneServer/lune` (Core Media Server)

This document describes the architecture, conventions, and engineering invariants of **Lune Server** (`github.com/LuneServer/lune`) and how it fits into the wider Lune platform.

> **Mandatory Branch Workflow:** Never commit directly to `main` or pile unrelated changes onto an existing branch. Start every distinct task (feature, fix, or doc change) on its own branch from an up-to-date local `main` (fetch and fast-forward `main` first, then `git switch -c <type>/<short-topic> main`, e.g. `fix/unraid-permissions`; if local `main` cannot fast-forward to `origin/main` or has commits not on `origin/main`, use the freshly fetched `origin/main` as the start point instead). For parallel or concurrent work, or when the working tree already holds uncommitted changes from another task, use a separate worktree (`git worktree add ../lune-worktrees/<topic>/lune -b <type>/<topic> main`, substituting the freshly fetched `origin/main` as the base under the same fallback) instead of switching branches in place; for cross-repo tasks put all three worktrees under the same `../lune-worktrees/<topic>/` parent (`lune`, `lune-web`, `lune-brand`) so the `../lune-web`/`../lune-brand` paths below resolve to the task branches. Keep each branch scoped to one concern, run `git status` before editing to confirm what you're building on, and when a task spans repos (`lune`, `lune-web`, `lune-brand`), use a same-named branch in each. Do not merge, rebase onto, or push unless the user asks.

> **Mandatory Maintenance Rule:** Whenever you implement new functionality or change existing architecture (packages, HTTP endpoints, SQLite migrations, environment variables, streaming behavior, deployment manifests, or cross-repo contracts), **you must update this `AGENTS.md` in the same change**. If it changes API contracts or static asset expectations consumed by the web client, update `lune-web/AGENTS.md` accordingly.

## 1. Lune Platform Ecosystem

Lune is a standalone, single-container self-hosted media platform (*"Your universe. Your media."*) built across three repositories under `github.com/LuneServer`:

| Repo | Local Path | Role |
|---|---|---|
| **`LuneServer/lune`** (this repo) | `../lune` | Core Go server: embedded ACME/HTTPS edge, security/auth, SQLite catalog, library scanner/watcher, metadata enrichment, Direct Play & FFmpeg HLS streaming, OpenAPI 3.1 API, and static SPA host. |
| **`LuneServer/lune-web`** | `../lune-web` | Flagship React 19 + TypeScript + Vite + Tailwind CSS v4 web client and admin console. Compiles to a static `dist/` bundle served directly by `lune` via `LUNE_WEB_DIR` (no Node.js runtime in production). |
| **`LuneServer/lune-brand`** | `../lune-brand` | Visual identity source of truth: Horizon SVG/PNG marks, `BRAND.md`, and dark-first celestial design tokens (`tokens.css`, `tokens.json`). |

Future native clients (`lune-ios`, `lune-tv`, `lune-android`) will consume the same OpenAPI 3.1 contract (`/openapi.json`), Bearer/refresh auth + RFC 8628 device login, and HMAC-signed streaming endpoints.

## 2. Core Architectural Principles

1. **Zero Separate Reverse Proxy:** Lune owns TLS termination natively via embedded CertMagic ACME (HTTP-01 / TLS-ALPN-01, plus Cloudflare DNS-01). `RemoteAddr` is authentic by default; `X-Forwarded-For` is ignored unless the peer matches explicitly configured `LUNE_TRUSTED_PROXIES`.
2. **Single-Container, Zero-CGO Footprint:** Static Go binary (`CGO_ENABLED=0`) using pure-Go SQLite (`modernc.org/sqlite`), packaged with `ffmpeg`/`ffprobe` in Debian slim (`Dockerfile`). Persistent state lives in `/data`; media mounts are read-only (`/media`).
3. **Contract-First HTTP API:** JSON API endpoints are registered through `huma/v2` on `chi`, emitting a canonical OpenAPI 3.1 spec at `GET /openapi.json` and interactive docs at `GET /docs`.
4. **Signed Media Delivery:** Clients negotiate playback via `POST /api/v1/items/{id}/playback` and receive short-lived HMAC-SHA256 signed URLs (`/stream/direct/{token}`, `/stream/hls/{token}/{file}`, `/stream/sub/{token}/{file}`) so players never send cookies or long-lived Bearer tokens in media URLs.

## 5. Key Implementation Patterns & Invariants

### HTTP & OpenAPI Layer (`internal/api`, `internal/web`)
- **Middleware order** in `api.NewHandler`: `RequestID` -> `Recoverer` -> `security.BodyLimitMiddleware` -> `security.HeadersMiddleware` -> `security.EdgeGuardMiddleware` -> `security.CompressMiddleware` -> `requestMetaMiddleware` -> `adminLANOnlyMiddleware` -> `csrfMiddleware` -> `optionalAuthMiddleware`.
- **Auth enforcement:** `optionalAuthMiddleware` resolves `Authorization: Bearer <token>` or the `lune_session` HttpOnly cookie into request context. Handlers explicitly check `currentPrincipal(ctx)` for 401 and `user.Role != "admin"` for 403.
- **Typed JSON endpoints vs. raw Chi routes:** Use `huma.Register` for all JSON API endpoints so `/openapi.json` stays canonical. Use raw `chi.Router` routes only for binary/streaming responses (`/api/v1/items/{id}/artwork/{kind}`, `/api/v1/items/{id}/artwork/chapters/{index}`, `/api/v1/items/{id}/trickplay/{sheet}`, `/api/v1/artwork/people/{file}`, `/api/v1/users/me/avatar`, `/api/v1/users/{id}/avatar`, `/stream/direct/{token}`, `/stream/hls/{token}/{file}`, `/stream/sub/{token}/{file}`).
- **SPA safety:** `web.NewSPAHandler` must never hijack `/api/`, `/stream/`, `/healthz`, `/docs`, or `/openapi.*`.
- **No write timeout:** `edge.Server` deliberately leaves `http.Server.WriteTimeout` at `0` so long-lived media streams are never prematurely terminated.

### Persistence (`internal/store`)
- **Split WAL pools & tuning:** Always use `s.db` (`MaxOpenConns(1)`, `_txlock=immediate`, 64 MiB cache, 256 MiB mmap, `temp_store=MEMORY`, `busy_timeout=10000`) for writes and `s.reader` (4–8 `query_only(ON)` conns, 32 MiB cache, 256 MiB mmap) for **all reads** (including hot-path `auth.go` session/user lookups) so concurrent browsing and artwork requests never serialize behind the single writer connection or scanner writes. `Store.Close()` runs `PRAGMA optimize` and a passive WAL checkpoint.
- **High-scale scanning & search:** Library scans flush items in batched prepared transactions (`UpsertMediaItemsBatch`, 100 items/tx) and fingerprint unchanged files via the covering index `idx_media_items_fingerprints`. Media and series search queries use the trigger-maintained `media_items_fts` FTS5 table (`unicode61 remove_diacritics 2`) via `buildFTSQuery`.
- **Migrations:** Add new schema changes as append-only numbered files in `internal/store/migrations/` (e.g., `010_*.sql`). Never edit already-applied migration files; `Store.migrate` applies them in lexical order inside transactions with `PRAGMA foreign_keys = OFF` outside the transaction followed by `PRAGMA foreign_key_check` so table-rebuilding migrations stay safe.

### Security & Auth (`internal/auth`, `internal/security`)
- Passwords are min 8 chars, hashed with Argon2id (PHC format) and timing-equalized on unknown usernames via `dummyHash`.
- Web logins set `HttpOnly`, `SameSite=Lax`, `Secure` (when `EdgeModeACME`, `https://` `PublicURL`, or trusted `X-Forwarded-Proto: https` via live `runtimeNetwork`) cookies; app logins return `access_token` + rotating `refresh_token`.
- Runtime network & access-mode settings persist in `server_settings["network_config"]` (loaded on startup in `cmd/lune/main.go` via `config.ApplyStoredNetworkConfig`). Switching among `local`, `proxy`, and `tailscale` via `PUT /api/v1/admin/network/config` hot-reloads `ClientIPResolver` and live `edge_mode`/`public_url` immediately; switching to/from or modifying `acme` persists and signals `restart_required: true`.
- Brute-force protection uses `AuthRateLimiter` (5 failures / 10m -> progressive lockout 30s..15m), returning HTTP `429` with `Retry-After`, and feeds lockouts into `security.EdgeGuard` (sharded per-IP rate limiter + auto-ban on repeated auth lockouts, forged `/stream/*` tokens, or unauthenticated API probing; managed via `/api/v1/admin/security/bans`). Invite inspection/acceptance is also rate-limited per IP.
- Pure-Go RFC 6238 TOTP two-factor authentication (`/api/v1/users/me/totp/{setup,enable,disable}` and `/api/v1/admin/users/{id}/totp` reset) issues 8 SHA-256-hashed one-time recovery codes; `POST /api/v1/auth/login` signals `X-Lune-TOTP-Required: true` when a TOTP-enabled account omits `totp_code`.
- Invite tokens are 256-bit random values stored only as SHA-256 hashes in `user_invites`; raw tokens are returned once at creation. Invite acceptance atomically validates expiry/revocation/use limits, creates the account with library grants, and increments `use_count`.
- **Per-user library ACLs:** Admins and users with `all_libraries=1` have unrestricted access. Restricted members (`all_libraries=0`) are constrained to `user_library_access` rows across libraries, items, artwork, series, playback negotiation, watch progress, Continue Watching, Next Up (`GET /api/v1/playback/next-up`), and watchlist/favorites. `UserPreferences` includes `combine_next_up` (defaults to `true`) for combining Next Up into Continue Watching on clients, `show_chapter_markers` (defaults to `true`) for drawing chapter tick marks on player scrub bars (stored in the `preferences` JSON, no column; Skip buttons read `PlaybackPlan.segments` and are unaffected), `poster_badges` (defaults to empty / none; validated values: `resolution`, `hdr`, `dual_audio`, `seasons`, `rating`) for configurable poster overlay badges, and `auto_skip_intro` / `auto_skip_recap` / `auto_skip_credits` (`off` | `countdown` | `instant`; defaults `countdown` / `countdown` / `off`; missing or empty values are filled with the defaults by `ParseUserPreferences` and on PATCH, unknown values are a 422). `countdown` means clients skip after a 5 s countdown the viewer can cancel; `auto_skip_credits` covers `outro` and `preview` segments and clients only apply it to episodes (movie credits are never auto-skipped).
- User avatars (PNG/JPEG/WebP, max 2 MiB, sniffed via `http.DetectContentType`) are stored under `<DataDir>/avatars/` and cleaned up on avatar deletion or user removal.
- Security-relevant events (login, lockout, password changes, user admin actions, invite lifecycle, session revocation, device approvals) are recorded in `audit_events`.

### Library, Metadata & Streaming (`internal/library`, `internal/metadata`, `internal/stream`)
- **Scan progress:** `ScanStatus.total` is the number of candidate media files found by the directory walk (`0` while the walk is still running, so clients show an indeterminate state). `scanned` counts files fully handled: unchanged files (also counted in `skipped`) advance it during the walk, new/modified files advance it as each is probed or fails, so `scanned/total` is monotonic and reaches 100% at completion. `POST /api/v1/libraries/{id}/scan` (async) is idempotent: if a scan is already running it returns the live status instead of an error.
- Scans are incremental by file size, mtime, and `metadata_version` (`CurrentMetadataVersion`, currently 4) unless `force=true`. When a remote enricher (TMDB) is configured, items indexed under an older `metadata_version` (or before TMDB was configured) are automatically backfilled on startup via `Watcher` (`BackfillStaleLibraries`) and on incremental scans, then skipped on subsequent scans once upgraded. `ScanSync` detaches from the HTTP request context (`context.WithoutCancel`) so a browser navigating away never aborts a scan or fails in-flight batches. Failures are recorded via `recordItemErr` into `ScanStatus.Errors`, `LastError`, and a bounded `ErrorSamples` list (`{path, message}`, max 10) returned by `/api/v1/libraries*` so the admin console can show *why* files failed.
- **First-class Anime (`kind = "anime"`):** Supports mixed Anime Series and standalone Anime Films in one library, fansub `[Group] Title - 01` / ordinal season / 4-digit absolute numbering / OVA & Specials (`Season 0`) parsing, anime-ranked TMDB matching (preferring Animation genre `16` + Japanese origin) with automatic absolute-to-seasonal episode mapping, MKV chapter probing (`intro`/`outro`/`recap`/`preview`), sidecar `.ass`/`.ssa` pure-Go WebVTT conversion, on-demand FFmpeg extraction & caching of embedded MKV text subtitles (`/stream/sub/{token}/embedded-{idx}.vtt`; embedded ASS/SSA is pulled as `-f ass` and converted by the same Go converter, see below), and smart user-preference/anime Sub/Dub audio & subtitle auto-selection (auto-selecting Japanese audio + full subtitles when subbed, or English audio + forced Signs & Songs when dubbed).
- Metadata precedence during scan/refresh: filename parser (including embedded `{tmdb-...}` / `[tmdbid-...]` / `{imdb-tt...}` path tags) -> `ffprobe` streams & chapters -> local `.nfo` (including parent `tvshow.nfo` for `Season` subfolders) & local artwork -> previously pinned `tmdb_id` (preserved across force re-scans) -> optional TMDB enricher (direct ID lookup when `tmdb_id` is known, otherwise multi-signal candidate scoring across normalized title similarity, year proximity, vote/popularity confidence, and anime Animation/JP preference; TMDB posters are eagerly deduplicated under sharded `<DataDir>/artwork/tmdb/<size>/<shard>/<file>` paths while backdrops and episode stills are lazily materialized on first request via `LazyArtFetcher.EnsureArtwork`/`Service.ResolveArtwork`, with in-flight deduplication, atomic temp-file renames, and detached 15s singleflight downloads shared with lazy `FetchPersonPhoto` fetches so client cancellation does not abort cache fills; both `/api/v1/items/{id}/artwork/{kind}` and `/api/v1/artwork/people/{file}` map genuine 404/invalid paths to `404` and transient upstream errors/timeouts to `503`/`504` with `Cache-Control: no-store`).
- **Episode titles:** a matched TMDB episode name replaces the filename-derived title (even a non-placeholder one, since fansub text is often release junk or a different translation). An explicit local `.nfo` `<title>` is kept unless it is a placeholder, and a placeholder TMDB name (`Episode 5`) never replaces a real local title (`preferRemoteEpisodeTitle`). Fallback titles from filenames go through `cleanEpisodeTitle`, which drops bracket/paren/brace tags, resolution/codec tails, `+`-joined release tags (`+SubsPlus-`), trailing source tags (`CR`, `AMZN`, `MULTi`, ...) and a leading episode number (`001 - `, `E01`, `#01`, or a number equal to the episode number); clients prefix the episode number themselves (`1. Title`).
- **Series grouping:** series are grouped by `(library_id, series_title COLLATE NOCASE)` and keyed in URLs by `series_title`. Because releases spell one show differently, every scan ends with `Store.CanonicalizeSeriesTitles`, which rewrites episodes sharing a series `tmdb_id` to the title most of them use (ties go to the earliest regular episode), moves unmatched episodes whose normalised title (`NormalizeSeriesKey`: case, punctuation, apostrophes and the articles a/an/the ignored) equals a spelling of exactly one TMDB-bound show into that show, and merges the remaining unmatched episodes by normalised title. This also repairs existing libraries on the next scan, including unchanged files.
- Movie provider tags come from the filename and its own folder. For episodes, catalog `tmdb_id` and `imdb_id` identify the series; IDs from the episode sidecar are stored separately as `episode_tmdb_id` and `episode_imdb_id`. An IMDb ID alone does not replace an existing TMDB binding during a scan.
- Playback negotiation chooses the cheapest valid path: `direct` (HTTP Range `ServeContent`) -> `remux` (zero-transcode fMP4 HLS with `-c:v copy`, `-tag:v hvc1` for 4K HEVC, and `-c:a copy` when the selected audio track is already client-compatible fMP4 audio) -> `transcode` (fMP4 HLS with startup-probed `videotoolbox` / `nvenc` / `vaapi` / `qsv` / `software` `libx264`, real startup probes for `tonemap_vaapi` and `libplacebo`, hybrid VA-API GPU decode + `scale_vaapi` downscale before CPU `zscale`/`tonemap` when `tonemap_vaapi` is unsupported on older Intel/AMD GPUs, automatic HW-to-SW fallback on startup failure, `-fps_mode passthrough`, `aresample=async=1000` without `first_pts=0`, fMP4 `movflags=+negative_cts_offsets`, 3s keyframe alignment, and optional FFmpeg `overlay` burn-in for PGS/VobSub/DVB bitmap subtitles). Selecting the primary (first) audio track avoids unnecessary remuxing, and 10-bit H.264 / unsupported HDR / Dolby Vision profiles automatically negotiate transcoding.
- HLS sessions with known duration serve a complete `#EXT-X-PLAYLIST-TYPE:VOD` playlist (`index.m3u8` with `#EXT-X-ENDLIST`) plus an RFC 8216 multivariant `master.m3u8` (declaring `CODECS` and `CHANNELS="16/JOC"` for E-AC-3 Dolby Atmos remuxes), transparently restart FFmpeg with `-start_number` and `-output_ts_offset` on out-of-window segment seeks, and apply segment-distance `SIGSTOP`/`SIGCONT` throttling (pausing once 90s ahead, resuming within 45s) so 4K remuxes do not peg a CPU core or fill `/data/transcode`.
- HLS segment names are strictly validated (`^(master\.m3u8|index\.m3u8|init\.mp4|seg_\d{5}\.(m4s|ts))$`) to prevent path traversal, and embedded text subtitle extraction uses per-track singleflight deduplication with `-vn -an -dn`.
- **Skip segments (`internal/segments`):** `PlaybackPlan.segments` (`kind` `intro`|`recap`|`outro`|`preview`, `start_ms`, `end_ms`, `source` `chapter`|`introdb`, sorted by start) is what clients use for Skip buttons and auto-skip; `chapters` stays the chapter list/tick marks. Skippable container chapters become segments first (adjacent same-kind chapters merge). IntroDB (`GET https://api.introdb.app/segments`, no API key; series `imdb_id` + `season`/`episode` for episodes in TVDB aired order, `is_movie=true` for movies) fills only the kinds the chapters do not cover (`intro`, `recap`, `outro`). IntroDB segments starting past the file's duration or ending more than 5 s after it (a different cut) are dropped, others clamped to the duration; segments under 1 s are dropped. Lookups are cached in SQLite `introdb_cache` (14 days when any segment was found, 2 days when none, rows older than 90 days pruned at most daily), served stale while a detached refresh runs, backed off for 15 min per key after a failure, and fetched in a detached goroutine (10 s timeout) that negotiation waits on for at most 1.5 s (`DefaultWaitBudget`), so a slow IntroDB never delays playback much and the result is cached for next time. Negotiating an episode also prefetches the next episode's lookup. Only the title's IMDb ID and season/episode leave the server (User-Agent `Lune/<version>`). Admins can turn lookups off with `introdb_enabled` in `streaming_config` (`GET/PUT /api/v1/admin/streaming/config`; default `true`, a saved config without the field keeps `true`, a PUT that omits it keeps the current value); chapter segments are always returned.
- Stream tokens expire after 6h and bind `sid`, `uid`, `iid`, and `mode`.
- **Chapter Still Thumbnails:** Maintenance (`generate_chapter_thumbnails`, default `true`) sequentially generates 480px JPEG chapter stills via single-threaded FFmpeg (`-threads 1` for decoder and encoder plus `-filter_threads 1`, reniced to 15 like trickplay; cropdetect samples likewise; with HDR tone-mapping + SDR fallback, working through the whole backlog in one run, yielding immediately when a scan or any playback is active) into `<DataDir>/artwork/chapters/<item_id>/<index>.jpg` via atomic `.tmp.jpg` renames and prunes stale chapter indices. **Black bars are cropped:** before (re)building a title's stills, `detectBlackBars` (`internal/maintenance/crop.go`) runs FFmpeg `cropdetect` (`limit=0.094` fraction so 8-bit and 10-bit HDR behave alike, keyframes only, 4 frames per sample) at 15/30/45/60/75/90% of the runtime (last chapter end) and merges the samples into their bounding box, so a dark scene can never over-crop; axes with bars under 2% are left alone, pictures under 40% of the frame or fewer than 2 usable samples mean no crop, and offsets/sizes are kept even. The result is stored per title in `<item_id>/stills.json` (`version` = `chapterStillsVersion` (2), `source_mtime`, `crop`) and prepended as `crop=W:H:X:Y` to the still filter chain. Titles whose `stills.json` is missing, older, or for a different file mtime have all stills rebuilt once. `ChapterInfo.thumbnail_url` carries `?v=<still mtime>` so regenerated stills bypass the 7-day client cache. A still is current when its mtime is ≥ `media_items.file_mtime` (stored as **Unix nanoseconds**); chapters FFmpeg cannot extract get an empty `<index>.failed` marker and are not retried until the file changes. A pass that yields to playback/scans arms a single background watcher (`Status.chapters_resume_pending`) that re-runs the `chapter_thumbnails` task (trigger `resume`) once the server has been idle for 90s (polling every 15s, abandoned after 24h); `POST /api/v1/admin/maintenance/cancel` (`CancelRun`) also drops a pending resume. `cleanOrphanedArtwork` preserves live item chapter directories while removing orphaned ones. `GET /api/v1/items/{id}` and `POST /api/v1/items/{id}/playback` populate `ChapterInfo.thumbnail_url` (`/api/v1/items/{id}/artwork/chapters/{index}`) via a single `os.ReadDir` only for stills present on disk, served with library ACL enforcement and `Cache-Control: private, max-age=604800`.
- **Trickplay (scrubbing previews):** Optional maintenance task (`generate_trickplay`, default `true` for fresh installs (a saved `maintenance_config` keeps its stored value; omitted in a PUT body = `false`); `trickplay_interval_seconds` 2–60, default 10; `trickplay_width` even 160–480, default 320; all `required:"false"` with zero values normalized to defaults; task `trickplay`) tuned for the smallest storage at the best accuracy the source allows. Stage 1 is one FFmpeg pass per item with `-skip_frame nokey` (keyframes only), `-threads 1`/`-filter_threads 1`, `fps=1/N:round=down` → optional black-bar `crop=W:H:X:Y` (reused from the chapter stills' `stills.json` when it matches the file mtime and `chapterStillsVersion`, otherwise detected with the same `detectBlackBars`, waiting within the pause budget while busy) → `scale=W:W*9/16:force_original_aspect_ratio=decrease:force_divisible_by=2:flags=bicubic` (tiles fit a 16:9 box, so 2.40:1 tiles are 320×134 and 4:3 tiles 240×180; bicubic because `fast_bilinear` kept grain as aliased noise and doubled sheet size) → `mpdecimate` (drops tiles nearly identical to the previous one: static shots, black frames, credits, or one keyframe sampled twice when the GOP is longer than the interval) → `showinfo` (records each kept tile's `pts_time`) → `tile=10x10` into lossless PNG sheets; HDR is tone-mapped with SDR fallback. Stage 2 encodes each sheet with the smallest format this FFmpeg supports, probed once per process: AVIF via `libsvtav1` (preset 8, CRF 35, `lp=1`) or `libaom-av1`, else WebP (`libwebp` q60), else JPEG (q5). All FFmpeg calls run reniced to 15 and are `SIGSTOP`ped while a scan or any playback is active (non-Unix: stopped and retried next run), with a 6h per-run pause cap (`skipped_trickplay_busy`) and a 90-minute CPU budget per call (kernel CPU time from `/proc/<pid>/stat` on Linux, so a reniced job starved by other work is not mistaken for a stuck one; overrunning it writes the `failed` marker; unpaused wall time stands in off Linux; a separate 6h unpaused wall-time cap catches I/O stalls and skips the item for the run without a `failed` marker); a run works through the whole backlog (no per-run item cap). Sheets build in `<DataDir>/artwork/trickplay/<item_id>.building/` and atomically replace `<item_id>/` with `manifest.json` (`metadata.TrickplayManifest` v3: `format`, `crop`, interval, tile geometry, `thumb_count`, `sheet_count`, `source_mtime` = `file_mtime` ns, `configured_width`, `generated_at`, and `timestamps_ms` only when tiles were dropped). Items are rebuilt only when file mtime, settings, manifest version or the best available format change; failed builds write a `failed` marker keyed to all of those. Run reports include `trickplay_bytes` (total on-disk size). `POST /api/v1/items/{id}/playback` includes `trickplay` (`format`, `interval_ms`, `thumb_width`, `thumb_height`, `columns`, `rows`, `thumb_count`, optional `timestamps_ms`, `sheet_urls` with `?v=<generated_at>`) only when a manifest exists; clients pick the last tile whose timestamp is ≤ the hovered time (`n*interval_ms` when `timestamps_ms` is absent). AVIF sheets need AVIF-capable clients (current browsers; iOS/tvOS 16+). Sheets are served by the raw ACL-enforced `GET /api/v1/items/{id}/trickplay/{n}.{avif|webp|jpg}` route (validated by `^\d{1,5}\.(avif|webp|jpg)$`, matching `Content-Type`, `Cache-Control: private, max-age=604800, immutable`). Orphaned-artwork cleanup preserves trickplay directories of live items.
- **New media gets stills/trickplay right away:** `library.Service.SetMediaChangedHook` (wired to `maintenance.Service.NotifyMediaAdded` in `cmd/lune/main.go`) fires after a scan finishes whenever it saved new files or files whose size/mtime changed (metadata-only re-indexing, e.g. backfill or force re-scans of unchanged files, does not). If automatic housekeeping (`enabled`) and `generate_chapter_thumbnails` and/or `generate_trickplay` are on, it queues one internal pass (trigger `new_media`, `task` empty in the report, `Status.new_media_pending` while queued) running just those enabled tasks once the server has been idle for 30s (no scan, no playback, no other pass; polled every 5s, abandoned after 24h). A pass already running lists its items when its chapter/trickplay step starts and does not see media added later, so the queued pass waits for it to end and then runs; notifications coalesce (at most one queued pass, plus one follow-up for media added while it runs). `CancelRun` drops a queued pass. Background passes (`resume`, `new_media`) do not move a rolling (no `schedule_time`) schedule.
- **Housekeeping yields to foreground work:** `maintenance.Service.busyReason` treats the server as busy when a library scan runs (`Library scan in progress`) or any client is playing (`Playback in progress`): a live FFmpeg HLS session (`ActiveTranscodeDirs`) **or** `stream.Service.HasActivePlayback`, which counts every negotiated session (direct play included) whose `LastSeenAt` is within `PlaybackActivityWindow` (45s). `LastSeenAt` is refreshed by negotiation, `/stream/direct` range requests, HLS fetches and `PUT /api/v1/items/{id}/progress` heartbeats (lune-web and Apple TV send one about every 10s while playing), so Apple TV direct play pauses chapter stills, black-bar detection and trickplay just like web HLS. The artwork sweep only skips during scans; cache cleanup, audit pruning and DB optimize are cheap and never yield.
- **Run outcome reporting:** every `RunReport` carries `outcome` (`completed`, `partial`, `skipped` when nothing requested could run, `canceled`) and `skipped: [{task, reason}]` (busy reasons above, or `FFmpeg not available`). `POST /api/v1/admin/maintenance/run?task=` returns `200` with these fields, and clients must show the reason instead of reporting success.
- **ASS/SSA → WebVTT (`internal/stream/ass.go`):** sidecars use `ASSToWebVTT` (plain text, historical output); embedded ASS/SSA tracks are extracted with FFmpeg `-c:s copy|ass -ignore_readorder 1 -f ass` (never FFmpeg's WebVTT muxer, which turns `\k` karaoke into inline `<00:00:01.000>` timestamps; `-ignore_readorder` keeps events in time order instead of the script's line order, which can jump back many minutes) and converted by `StreamASSToWebVTT` / `ASSToWebVTTFormatted` (keeps `<b>`/`<i>`/`<u>` from styles and overrides, like the old FFmpeg output), cached as `<item>_<mtime>_<idx>.ass2.vtt` so pre-fix caches are never served. All override tags are stripped (karaoke flattened, **ASS colours never emitted**, drawings skipped) and text is WebVTT-escaped. Unpositioned duplicate layers (same text, overlapping ≥ half the shorter duration) collapse into one cue. Positioned (`\pos`/`\move`) events that are on screen together on the same row, or directly above/below each other, are grouped (incremental union-find), and each group is cut into time slices: in every slice the visible events are laid out as rows (pieces left to right, rows joined with a newline, duplicate layers at the same point dropped, a repeated letter one glyph apart kept). This matches Aegisub karaoke templates, which redraw each syllable as per-character, highlight and base events over time. Word gaps come from positioned whitespace-only events (the template's space glyphs; dialogue text keeps trailing white space for this) or, without them, from the gap between neighbours against a per-glyph width table (`textUnits`, em calibrated from the row's lower quartile); each line reuses the spacing of its best-measured slice. When a line fades out while the next fades in on the same spot, the piece whose text stays on screen longer (chain of same-text events at that point) wins and the outgoing line is dropped. Slices that read the same merge, slices under 350ms and per-character reveal steps fold into the finished line, so a karaoke line is one cue with its source text (verified on a real fansub OP/ED: 66/66 lyric lines exact). Positioned cues get `line:Y%,center position:X%,center align:center` (box centre, clamped to 8–92% / 10–90%); unpositioned `\an7-9` cues get `line:6%,start`, `\an4-6` `line:50%,center`; bottom-aligned dialogue gets no settings and is byte-identical to the old output (golden tests in `internal/stream/testdata`, generated karaoke-template fixtures in `ass_karaoke_test.go`). Streaming flushes a group once the newest event starts at or after its end, so embedded subtitles still arrive progressively. The Apple TV overlay (`lune-apple` `AetherSubtitleOverlayView.swift`, `SubtitleTextGrouper`) applies the same rules to AetherEngine's cues.
- Completing an item (`UpsertPlaybackProgress` with `completed = true`, automatically at ≥92% or explicitly marked watched) atomically removes it from the user's Watchlist while preserving Favorites.

## 6. Build, Test & Verification Commands

Run these before concluding any backend change (matches `.github/workflows/ci.yml`):

```bash
go vet ./...
go test -race -count=1 ./...
CGO_ENABLED=0 go build -trimpath -o /tmp/lune ./cmd/lune
```

Local development server:
```bash
go run ./cmd/lune
# Or serving a built lune-web bundle:
LUNE_WEB_DIR=../lune-web/dist go run ./cmd/lune
```

Release builds inject the tag **without** its leading `v` (tag `v0.1.0-beta.1` -> `version.Version = "0.1.0-beta.1"`) so API/CLI versions stay plain SemVer; clients add the `v` prefix for display.

## 7. Keeping Documentation Up to Date

When implementing new functionality in `lune`, check and update:
1. **This file (`AGENTS.md`):** Update the package layout, environment variable table, invariants, or verification commands whenever they change.
2. **`deploy/docker-compose.yml` (and `LuneServer/unraid-templates`):** Add any new user-facing `LUNE_*` environment variables or volume/device requirements.
3. **Cross-repo impact:** If you add or modify `/api/v1/*` routes or DTO fields, note or apply matching updates in `../lune-web/src/lib/api.ts` and `../lune-web/AGENTS.md`. Make those edits on the same-named branch in `../lune-web` (or in the matching worktree when that checkout has uncommitted changes from another task), never on whatever branch happens to be checked out there.
